# Preserve the authenticated Dress skeletal export route

The retained export base-pose feature applies to supported local same-rig
inputs. Generated Dress manual controls also depend on external Curve objects
through native Spline IK and exact point Hooks. Those inputs are outside that
new base-pose contract.

The ordinary exporter now recognizes this existing specialized graph only
after fresh source/native ownership, hierarchy, wire geometry, Hook binding,
manual/deform constraints and generated influence-driver validation. Every
external constraint endpoint must belong to that exact proved Dress closure;
unrelated external objects or drivers still refuse. Actual-surface ownership
and physical-channel guards run before retained-base preparation. Direct Dress
export remains pending behind its original refusal.

Validated Dress exports retain the existing worker and its explicit omission
of supported surface physics. Plain Manual setups work with no surface-proof
list. Recognition also covers the unparented separate native Dress graph, but
the unchanged worker's separate-accessory skeleton-filter limitation remains;
this change does not claim a successful standalone separate-rig FBX. A legacy Cloth graph
requires its existing fully validated Manual endpoint. Rigging keeps its own
authenticated export DTO and route.

The host repeats native admission immediately before writing its disposable
snapshot, after ending transient Hair preview. It does not update generation
records, source pointers, geometry, weights, keys or artist pose. The sidecar
records the frozen policy **existing-authenticated-Dress snapshot; retained
base unsupported**, source-record hashes and the authenticated closure hash.

This compatibility route retains previous snapshot semantics. It does not
apply a retained Action base pose to Dress inputs and does not claim that a
sparse Dress Action alone determines the output. Supporting that stronger
contract would require explicitly retaining all Curve/Hook and other external
inputs and verifying its native endpoint equivalence separately.

If an Action already has a retained base pose, specialized Dress export refuses
to ignore it. Choose **Clear Export Base Pose** explicitly to use the existing
Dress snapshot contract. That action removes only its two saved export-base
metadata fields, with the same active-Custom/Source protections as capture;
keys, current pose and other Action metadata stay intact. Clear is also useful
after making a plain Action fully keyed, when it no longer needs a saved base.

The withdrawn 143 candidate and all earlier evidence remain intact. Local
component tests do not imply artist refresh, scene/preferences save, Unity
acceptance or Git upload.
