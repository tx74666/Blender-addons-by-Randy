## User workflow

- Generate/Update records the original skeleton and Rest baseline. For controls already generated by an older version, run Update once.
- In Pose Mode, double-click an Original-bone Pose in the Asset Browser. The tool applies the saved channels and matches the current controllers. Only the keyed region and its natural descendants change; the original asset is not rewritten.
- Matching preserves the current IK/FK mode when it reproduces the pose. A pose outside the IK solver's representation uses matched FK internally and exposes the corresponding controls. The user does not need a manual conversion or another asset.
- Body Controls → Edit Weights keeps the visible pose, selects the configured/bound mesh and exposes native deform bones. A hand target maps to the hand deform group; a Pole maps to the middle joint. Ambiguous mesh selection requires choosing the mesh or setting Character Setup → Body.
- Back to Controls restores the prior display, selection, mode and active vertex group. Edited weights remain. The return button stays available while the mesh is active.
- No Rest changes, added bones, weight recalculation, constraint removal, mesh changes or Shape Key authoring are performed by these two operations.

## Compatibility and limitations

The old Fist file stores Action values and the CoshaRig slot but no authoring skeleton/Rest snapshot. The user recalls no substantive original-bone change. Its historical authoring Rest cannot be reconstructed or independently verified. The current generation-time native skeleton is the explicit compatibility baseline; later Rest/structure changes are rejected rather than silently reapproved on rebuild.

Single-frame native transform Pose assets are supported. Missing/foreign/ambiguous slots, unsupported channels, transform drivers and unrepresentable constraints are rejected with rollback. Assets authored on generated controls and ordinary rigs retain the official Pose Library application path. Custom user keymaps are not overwritten.

Interactive tests cover the original Fist copied into the validation file's local Asset Browser. External asset isolated reading is separately covered by a real Blender library test. Exhaustive motions, arbitrary third-party rigs/assets, every nonuniform-scale or constraint combination, and Pose application GUI Redo were not verified (未验证). Weight workspace Undo and Redo were verified.

## Changes

Seven runtime files differ from 0.62.17:

- `control_pose_assets.py` (new): native compatibility baseline, isolated asset reading, parent-ordered native pose reconstruction, existing limb/spine matching, safe Auto Key transaction and Asset Browser dispatcher.
- `control_weight_paint.py` (new): reversible weight workspace with Scene ID references, failure recovery and accessible return panel.
- `body_setup.py`: baseline recording after successful Generate/Update; refuse rebuilding during a weight-editing session.
- `body_setup_ui.py`: Edit Weights entry below Update.
- `bone_collections.py`, `bone_display_sync.py`: preserve temporary weight workspace visibility; guard structural changes during the session.
- `__init__.py`: registration, cleanup and version.

The dispatcher temporarily disables only the official addon's active, unmodified double-click binding because Blender's merged keymap placed it ahead of the new binding. Unregister restores the exact original item; the original operator and user/default keymaps are preserved.
