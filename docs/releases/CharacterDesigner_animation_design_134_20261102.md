## Editing files travel with the work

Animation > Advanced adds **Package Editing Files** and **Locate Editing Files**.
Packaging copies the active, retired and Current Rig checkpoint-owned Source
libraries and available Main Rig recovery packet into a new folder. The UI
then reconnects to the verified copies. Save the editing blend normally to
retain those locations; keep the blend and package in the same relative layout
when moving them. Packaging itself does not save the blend.

An independent locator maps unchanged logical identities to same-SHA physical
files. It does not rewrite row identity, historical SESSION/REFS, Current Rig
checkpoint text, original recovery permissions or Source content. Rebinding
also verifies the loaded Source curves. Moving a saved pair, Save As and a
subsequent move/Save As are covered by the private native checks.

New adopted Main Rig sessions retain a verified recovery packet in a persistent
content-addressed cache, so rebuilding the original exchange packet does not
remove the recovery input. Existing records are not silently rebased. A changed
or ambiguous file remains a refusal, with current edits and checkpoints kept.

The editing package excludes the blend itself and Unity publication routes.
It is not a new Unity workspace or a route migration. Unsaved blends and
cross-drive paths may retain absolute locations; the UI reports that those
locations are not portable. Captured Rigging/Composition and attached input
sessions require their separate dependency contract and are explicitly refused.
Missing native linked IDs are not repaired by a library reload.

## Sparse Actions have explicit export defaults

**Capture Export Base Pose** is available in worklist Advanced and the ordinary
Action export dialog. It saves the intended unkeyed inputs on the active local
Custom without changing current pose or keys. Future ordinary exports apply
those saved inputs only to a disposable snapshot and use the explicit export
start frame for the reference transform. Unkeyed trial posing and the current
timeline frame therefore do not silently become new export defaults.

Capture again deliberately to use a different base. Adding/removing enabled
channels or changing supported rig structure requires recapture; changing key
values alone keeps the contract usable. Capturing/removing/recapturing defaults
participates in collection publication identity, so an old unchanged receipt
cannot silently skip the changed defaults. Current-pose dependency fingerprints
can still conservatively report Changed; this delivery does not loosen them.

The first ordinary contract supports bounded local same-rig inputs, including
validated simple internal drivers and constraints. Unknown external or complex
dependency graphs require a separate bake and are refused. The existing
authenticated Rigging DTO retains its own export path. The established worker
bytes and Composition worker pins are unchanged. See
`CharacterDesigner_export_base_pose_20261102.md` for precise input boundaries.

Version 144 retains the existing strictly authenticated Dress manual and
actual-surface snapshot contracts, including their external generated wires.
They do not use an ordinary saved export base, and the sidecar says so. A
previously saved ordinary base must be explicitly removed with **Clear Export
Base Pose** before using that specialized path; it is never silently ignored.
Clear removes only its two metadata fields, with Source, pose and keys retained.
The existing separate accessory-rig skeleton-filter limitation remains distinct
from the restored shared Manual path. Unshipped draft143 was withdrawn after
this compatibility regression was found; all its files and receipts are retained.
